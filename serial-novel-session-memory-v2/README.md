# serial-novel-session-memory v2.0

AI 写长篇小说的跨会话记忆协议——让 AI 在每轮对话只有有限上下文的情况下，仍然记住伏笔回收日历、人物状态和卷间承诺，不靠模型记忆，靠结构化快照交接。

## 核心理念

长篇小说的敌人不是 AI 写得不好，而是**写到第 80 章时记不住第 12 章埋了什么**。v1.0 解决了 "5 章一段 + 手动贴快照" 的基础工作流，v2.0 在此基础上加入：

- **卷/弧分段**：按故事结构（非固定章数）划分会话，卷末做完整归档
- **三级快照**：轻量（每章，覆盖式）→ 标准（每段，归档式）→ 卷末（完整状态）
- **🔥伏笔距离感知**：🚨（1-2 章到限）→ ⚠️（3-4 章到限）→ 已超期，作者和 AI 都能看到大限
- **跨卷伏笔继承**：卷 1 未收的伏笔显式移交到卷 2，期限顺延
- **双轨持久化**：有文件能力的 AI 直接写文件；纯聊天环境由用户保存 AI 输出的文本块

## 文件结构

```
serial-novel-session-memory-v2/
├── SKILL.md                          # 核心协议（豆包/AI 的运行时规约）
├── references/
│   ├── snapshot-template.md          # 三级快照模板（轻量/标准/卷末）
│   ├── foreshadowing-guide.md        # 伏笔管理手册 v2.0
│   └── opening-prompt.md             # 开篇提示词（含恢复指令）
└── dsh-novel-forge-integration.md    # DSH + dsh-novel-forge 集成文档
```

## 适用环境

- **豆包 (Doubao)**：放入 `.user_skills/` 目录作为用户 skill
- **其他 AI 聊天**：`opening-prompt.md` 作为每段会话的开场提示词
- **DSH + dsh-novel-forge**：集成文档描述了哪些工具覆盖了协议的哪些功能

## 版本历史

- **v2.0** (2026-10)：卷分段 + 三级快照 + 伏笔距离感知 + 跨卷继承 + 双轨持久化
- **v1.0** (原始)：5 章一段 + 手动快照粘贴
