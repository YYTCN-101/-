# 连载小说会话记忆（Serial Novel Session Memory）v2.0

## Overview

解决长连载创作中"上下文随章节线性增长 → 会话疲劳"的结构性问题。核心原则：**会话内历史必然增长，任何会话内技巧都无法消除增长；唯一消除疲劳的路径是"会话分片 + 快照无损重置"**。快照是唯一跨段记忆源。

v2.0 核心改进：
- 分段从「固定 5 章」升级为「卷/幕自然边界」，不打断故事节奏
- 快照从「单一 1200 token」升级为「三级快照体系」（轻量/标准/卷末）
- 快照从「人工复制粘贴」升级为「双轨制」（有文件能力的写磁盘，纯会话的输出文本块供保存）
- 轻量快照覆盖式保留（段内只存最新 1 份，不累积膨胀）

---

## 一、核心协议（必须遵守）

### 1. 会话分片（第一优先）

以**卷/幕自然边界**为创作段，不再硬编码 5 章：

- 作者在设定中声明分段节点（如「第一卷第 1–8 章」「第二卷第 9–22 章」）
- 卷末生成标准或卷末快照，随即开新会话冷启动，历史归零
- 段内不换会话；跨段细节一律从快照读取，**禁止回翻更早会话的旧章全文**（回翻即破坏分片）

### 2. 三级快照体系

| 级别 | 触发时机 | 预算 | 内容 | 用途 |
|---|---|---|---|---|
| **轻量快照** | 每章（段内） | ≤400 token | 状态变更 + 伏笔变更（增量） | 段内衔接，下一章写前快速对齐 |
| **标准快照** | 段末 | ≤1200 token | 圣经压缩 + 状态 + 摘要链 + 伏笔台账 | 换会话冷启动 |
| **卷末快照** | 卷末 | 目标 2000 token（软上限） | 标准四段 + 全量伏笔对账 + 跨卷移交清单 | 跨卷存档与长期回溯 |

**卷末预算溢出处理**：超出目标值时按优先级裁剪——①摘要链先压缩 → ②非关键状态次之 → ③伏笔内容与关键事实**永不压缩**。

### 3. 轻量快照的 C1 规则（防累积膨胀）

轻量快照**覆盖式保留，段内始终只存最新 1 份**：

- 每章写完 → 生成轻量快照，覆盖上一章的轻量快照
- 段末生成标准快照后 → 轻量快照归档到文件（`快照/light-vX.X-归档.md`），不进入后续上下文
- 此规则确保上下文不因轻量快照累积而膨胀——10 章后仍只有 1 份轻量快照在上下文

### 4. 快照触发优先级（三档兜底）

快照触发按以下优先级，从高到低：

1. **作者显式声明**（最高优先）：作者说"本卷完""到这里结一段" → 立即生成对应级别快照
2. **设定中预声明节点**：作者在初始设定中写了「第一卷第 1–8 章」→ 第 8 章写完自动检测，生成卷末快照
3. **兜底回退**：连续无声明时，每 **5 章**自动生成标准快照并提示换会话

卷末快照**只在①②触发**，兜底只生成标准快照。

### 5. 双轨落盘（跨环境兼容）

快照的保存方式取决于运行环境：

- **有文件写入能力的环境**（如豆包桌面端、DSH、Cursor）：AI 将快照**同时**输出到会话 **和** 写入工作区文件 `快照/vX.X-级别.md`，防复制丢失
- **纯会话环境**（如 Web 聊天窗口）：AI 以独立代码块输出完整快照文本，提示用户保存为 `.md` 文件

两种环境的协议一致——区别仅在谁来执行"写入磁盘"这一步。

### 6. 回复结构

| 章节类型 | 回复内容 |
|---|---|
| **首章** | `【第1章正文】` + `【本章小结与台账变更】` + `【轻量快照·初始】`（建立状态基线，供第 2 章对齐） |
| **段内（非首章/非段末/非卷末）** | `【本章正文】` + `【本章小结与台账变更】` + `【轻量快照】（覆盖更新）` |
| **段末** | `【本章正文】` + `【本章小结与台账变更】` + `【标准快照·完整版】` + `【轻量快照归档提示】` + `【换会话提示】` |
| **卷末** | `【本章正文】` + `【本章小结与台账变更】` + `【卷末快照·完整版】（含全量伏笔对账与跨卷移交清单）` + `【作者伏笔决策请求】` + `【轻量快照归档提示】` + `【换会话提示】` |

> **卷末与段末互斥**：若某章同时是段末和卷末（如第一卷恰好 5 章），只生成卷末快照，不重复生成标准快照。卷末快照已包含标准快照的全部内容，且额外含全量对账与跨卷移交清单。

### 7. 疲劳信号

上下文占用 >70% 或已达段末/卷末 → 立即生成快照并提示换会话。

### 8. 会话内写作规则

- 每章只依据本条消息内容与段内近期上下文写作
- 跨段细节一律从快照的摘要/台账读取
- **禁止回翻更早会话的旧章全文**

## 二、快照模板（速查）

（完整模板、预算与压缩规则见 `references/snapshot-template.md`）

### 轻量快照（每章，≤400 token）

```
【轻量快照 vX.X｜第N章】
【状态变更】角色A|新位置|新状态 ｜ 角色B|持有物变更 ……
【伏笔变更】新增 V-00X（…）｜ 回收 V-00Y ｜ 推进 V-00Z（呼应章N）
```

### 标准快照（段末，≤1200 token）

```
【记忆快照 vX.X｜截至第N章】
【圣经·压缩】世界观一句话 ｜ 人物卡(名/外貌/性格/动机/关系) ｜ 文风规范
【状态】角色|位置|状态|关系 ｜ 角色|位置|状态|关系 ｜ 当前时间线
　　【关键事实·不可压缩】已死亡: … ｜ 当前境界: … ｜ 关键物品位置: … ｜ 不可逆事件: …
【摘要链】近5-8章逐章(情节+钩子) ｜ 更早阶段压缩摘要
【伏笔日历】V-000 已收@5 ｜ V-001 最迟18章回收(埋3,可提前)
【伏笔台账】未回收: … ｜ 已回收: …
```

### 卷末快照（卷末，目标 2000 token）

标准快照四段 + 以下扩展：

```
【全量伏笔对账】
- 未回收伏笔逐个状态审查：正常推进 / 悬置预警 / 建议移交下卷 / 建议废弃
- 每项附作者决策空间（回收 / 移交 / 留待后卷 / 废弃）

【跨卷移交清单】
跨卷: V-003 移交卷2, 期限顺延为卷2第X章
跨卷: V-007 移交卷2, 期限顺延为卷2第Y章（关联元素A/B需在卷2前期铺垫）
```

## 三、伏笔管理要点

（完整规范见 `references/foreshadowing-guide.md`）

- **编号唯一**：V-001、V-002…跨章唯一、永不复用
- **日历锚点**：标注"最迟第 X 章回收（可提前）"；距期限 ≤2 章强制标注"临近回收"，到期当章必须回收
- **章前核查**：写前列出本章须回收/须推进/可呼应的伏笔清单
- **章后对账**：新伏笔登记 / 回收标记 / 应推进未推进标"延后"
- **跨卷继承**（v2.0 新增）：卷末快照显式标注移交伏笔 → 台账状态字段同步更新为新卷期限 → 杜绝跨卷后期限悬空

## 四、使用流程

### 开场（新作品）
首条消息粘贴 `references/opening-prompt.md` 中的快速启动指令 + 你的设定（含分段节点声明） + 第 1 章任务。模型返回正文、小结与初始快照。

### 段内
发送本章任务（含伏笔事件行）→ 模型返回正文 + 小结 + 轻量快照 → 下一章继续。

### 段末
模型返回正文 + 小结 + 标准快照 + 换会话提示。复制快照或确认文件已落盘 → 开新会话 → 粘贴快照（或给文件路径，AI 读取）→ 循环。

### 卷末
模型额外返回全量伏笔对账与跨卷移交清单。确认作者的伏笔处置决策（回收/移交/废弃）后再开新会话。
